# World Server Config Startup Plan

Lifecycle: see the [scope status and criteria](spec.md).

## 1. Verify runtime prerequisites

Before the runtime campaign, follow `use-codex-vm` and the prepared-client smoke skill. Verify compatible profiles `1.20.1-forge`, `1.20.1-fabric`, `1.21.1-neoforge` and `26.1.2-neoforge`: `launch.json`, installed loader identities, Java 17/17/21/25, disposable world markers and the artifact-copy route. Inventory dedicated fixture markers and source seals for the same targets.

For missing dedicated fixtures, use existing `prepare-dedicated-ui-smoke-server.ps1` provisioning after validating inputs and its download plan. Do not silently create infrastructure or substitute loaders. Missing native clients or incompatible runners are explicit prerequisites. Compare the dedicated launcher's hardcoded loader coordinates with actual prepared profiles before selecting it.

## 2. Implement and review

Update the shared load path per the [design](technical-design.md). Keep loader callers on that path. Add focused regression checks in `ServerConfigFileTest`:

- full default output with absent parents (A1);
- migrated effective output and unchanged legacy bytes (A2);
- unchanged existing custom/malformed/commented files and repeated-load bytes (A3);
- deterministic generation failure retaining migrated values, plus read failure preserving the destination (A4).

Review every caller and the full diff before committing. Follow repository ordering: the conventional commit hook creates the PR before tests run.

## 3. Update player documentation

Update both GuideME `features/configuration.md` locale variants with the world path, startup generation and legacy migration. Correct directly contradictory ownership/validation wording there. Publish the corresponding configuration wiki page from reviewed canonical text, preserving unrelated wiki content. Retain the wiki revision and live readback (A6).

## 4. Verify the implementation head

After PR creation, run focused shared regression tests and shared JaCoCo verification/report, then required CI tests and all-target builds. Require 100% shared line and branch coverage. Bind results to the live PR head and distinguish local checks from GitHub checks.

Inspect `run-ui-smoke.ps1 -Changed -BaseRef origin/master -PlanOnly`. This storage change needs startup proof; a full rendering suite or planner fallback does not prove config creation. Reuse native launch and evidence paths, with only bounded scenario assertions needed to check the file.

For each of the four verified compatible profiles:

1. Launch the client to its menu before loading a world; record that the client-only phase creates no server file.
2. Start a disposable integrated world with no world server config. Verify the generated file, exact path and effective values without editing Options.
3. Start a disposable dedicated server with no world server config through the existing startup-only path. Verify generated bytes and clean stop.

Budget at least four client and four dedicated processes. Measure the first target's cold-start cost, then record remaining wall-time budget and bounded progress timeouts. Run targets sequentially. Unit tests cover migration, preservation and write failure; runtime runs prove the loader lifecycle and both server modes (A5). Retain logs, source/artifact hashes, config files, process IDs, timestamps and durations. Stop owned processes only; cleanly shut down CodexVM afterward and verify its VMX is absent from `vmrun -T ws list`.

## Completion gate

| Criteria | Change | Evidence |
| --- | --- | --- |
| A1-A3 | Shared lifecycle | Regression tests, complete generated values, original-file byte comparisons |
| A4 | Separate generation recovery | Failed-write regression preserving migrated values; warning includes path and cause |
| A5 | Existing loader startup routes | Integrated/dedicated startup and file evidence on all four targets; client-menu no-write observation |
| A6 | GuideME and wiki text | Reviewed locale pages, valid paths/links, wiki revision and live readback |

Finish only with all criteria proved at the implementation head, current required CI passing, reviewed PR merged and #535 closure/claim cleanup verified. Keep missing prerequisites and failed/pending checks visible until resolved.
